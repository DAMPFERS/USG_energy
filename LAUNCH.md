# Запуск на площадке (игровой режим)

Инструкция для человека, который готовит сервер энергосистемы купола к игре.
У каждого купола свой компьютер, свой щиток и своя ветка: купол 1 — `dome-1`, купол 2 — `dome-2`.

Игра идёт 50 часов: начало **27.10 в 11:30** (заселение, на панели — Сол 1, 11:30),
конец — 29.10 в 13:30 (Сол 3, 12:10). Время купола считается от **системных часов компьютера**.

---

## 1. Компьютер

- Python 3.10 или новее, git.
- Компьютер подключён к той же сети, что и умные реле щитка (роутер щитка, адреса `192.168.x.x`).
- **Системные часы и часовой пояс верные** (Москва). От них зависит игровое время.
  Если в сети нет интернета, проверьте время вручную перед стартом.
  - Linux: `timedatectl` (при необходимости — `sudo timedatectl set-timezone Europe/Moscow`).
  - Windows: «Параметры → Время и язык».
- Отключите сон и гибернацию: компьютер должен работать все 50 часов, от сети, а не от батареи.
- Желательно закрепить за компьютером постоянный IP в роутере — по нему участники открывают панель.

## 2. Код

Первый раз:

```
git clone https://github.com/DAMPFERS/USG_energy.git
cd USG_energy
git checkout dome-1                 # на компьютере второго купола — dome-2
```

Linux:

```
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Windows (PowerShell):

```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если код уже скачан — обновить: `git pull`.

## 3. Настройка `config/server.yaml`

Откройте `config/server.yaml` и проверьте:

1. **Часы — боевой режим:**
   ```yaml
   clock:
     mode: real
   ```
2. **Пароль организатора** — замените `admin_token: "change-me"` на свой.
3. **Реле щитка.** В разделе `lines` замените 13 строк `driver: sim` (виртуальные реле) на реальные реле
   своего щитка. Образцы — закомментированы в конце файла («1й щиток», «2й щиток»):
   ```yaml
   lines:
     - {id: 1, name: "Линия 1", driver: tuya, scale: 1, tuya: {device_id: "...", local_key: "...", ip: "192.168.8.73", version: 3.5}}
     ...
   ```
   Должно быть ровно 13 линий с `id` от 1 до 13. Ключи (`device_id`, `local_key`) и IP — актуальные
   для этого щитка (`smart_rele/get_keys.py`). `scale` — множитель «реальные Вт → кВт купола»:
   например, лампа 60 Вт при `scale: 20` даёт 1.2 кВт.
4. **Аккумулятор и правила** (`battery`, `rules`) — значения, согласованные с организаторами кейса.
   Их можно менять и во время игры из консоли организатора.
5. Начало игры — в `config/scenarios/mission.yaml` (`start: "2026-10-27 11:30"`). Обычно менять не нужно.
6. Прогноз: `data/forecast.csv` — солнце, `data/dust.csv` — запылённость (участникам не видна).
   Выгрузка запылённости для георазведки (спутниковые снимки каждые 1,5 ч): `python -m server.export_dust`.

Сохраните настройки щитка в ветку купола, чтобы не потерять:

```
git add config/server.yaml
git commit -m "Реле щитка купола 1"
git push
```

## 4. Проверка перед игрой

1. Запустите сервер:
   ```
   python -m server
   ```
   В выводе должно быть `часы: real x1.0` и не должно быть ошибок.
2. В браузере откройте `http://<IP компьютера>:8000` (на самом компьютере — `http://localhost:8000`).
   До 11:30 27.10 в шапке идёт обратный отсчёт `T−`, после — время купола `SOL 1 11:30:…`.
3. Во втором терминале (тоже в папке проекта и с активированным `.venv`) откройте консоль организатора:
   ```
   python -m admin
   ```
4. **Найдите, какое реле что питает.** Для каждой линии:
   ```
   blink 4            линия 4 помигает 3 раза — смотрим, где
   name 4 BIO-L       линия 4 = освещение BIOLAB
   names              проверить привязку
   ```
   Ключи потребителей: `HAB1-S`, `HAB2-S`, `FAB-S1`, `FAB-S2`, `BIO-S1`, `BIO-S2`, `MAIN-S1`, `MAIN-S2`,
   `HAB1-L`, `HAB2-L`, `FAB-L`, `BIO-L`, `MAIN-L`. Привязка сохраняется в `config/line_map.yaml`.
5. Проверьте, что все линии на связи. Линия с пометкой «НЕТ СВЯЗИ» означает, что реле не отвечает:
   проверьте его питание, IP и ключ.
6. С панели включите и выключите пару линий — реле должны щёлкать.

## 5. Старт игры

**Один раз перед игрой** сотрите всё, что осталось от тестов (история, терминал, блокировки, заряд АКБ):

```
Ctrl+C                      остановить сервер
python -m server --reset    запустить начисто
```

После этого сервер просто работает. Игра начнётся сама в 27.10 11:30, ничего нажимать не нужно.

Участники открывают в браузере `http://<IP компьютера>:8000`. Если у кого-то на панели прочерки
вместо цифр — **Ctrl+F5** (обновить страницу без кэша).

> ⚠️ **Во время игры `--reset` не использовать** — он сотрёт историю и состояние игры.

## 6. Во время игры

- **Сервер упал, компьютер перезагрузился, пропал свет** — просто запустите снова **без** `--reset`:
  ```
  python -m server
  ```
  Игра продолжится с текущего момента. Пропущенное время на графике участников отметится как «NO LINK»,
  в терминал придёт сообщение о восстановлении связи.
- Консоль организатора (`python -m admin`) можно закрывать и открывать в любой момент — на игру это не влияет.
  Справка по командам — `F1`. Основное:
  - `max 9.5` — верхняя граница потребления;
  - `bat capacity_kwh=40 max_charge_kw=5 max_discharge_kw=6`, `bat soc=50`, `bat off 10` / `bat on` — аккумулятор;
  - `set overload_grace_min=5 battery_off_min=15` — правила (`set` — список);
  - `crisis cancel` — сбросить все отсчёты и блокировки, если что-то пошло не так;
  - `solar 0` — после пылевой бури панели засыпаны: генерации нет; по мере очистки панелей экипажем
    повышайте коэффициент (`solar 0.3`, `solar 0.7`, …), `solar 1` — панели чистые;
  - `msg WARN Text` — сообщение участникам (по-английски).

  Изменения `max`, `bat …=…`, `set` сразу действуют и сохраняются в `config/server.yaml`.
- Все действия пишутся в `logs/actions_mission.log`, сообщения терминала — в `logs/terminal_mission.log`,
  история — в `logs/telemetry_mission.csv`.

## 7. Если что-то не так

| Признак | Что делать |
|---|---|
| На панели прочерки, график не рисуется | Ctrl+F5 в браузере. Если не помогло — проверить, что сервер запущен |
| «no link to dome» на панели | сервер не запущен или компьютер участника не в той сети |
| Время купола неверное | проверить системные часы и часовой пояс компьютера, затем перезапустить сервер |
| Линия «NO LINK» / «НЕТ СВЯЗИ» | реле не отвечает: питание, IP (`ping 192.168.8.x`), ключ в `server.yaml` |
| Панель не открывается с других компьютеров | открыть порт 8000: Linux — `sudo ufw allow 8000/tcp`; Windows — разрешить Python в брандмауэре |
| `git pull` ругается на изменённый `server.yaml` | закоммитить настройки щитка (`git commit -am "..."`) и повторить |

## 8. Держать сервер запущенным (Linux, по желанию)

Чтобы сервер не останавливался при закрытии окна терминала, запускайте его в `tmux`:

```
sudo apt install tmux
tmux new -s dome          # внутри: . .venv/bin/activate && python -m server
Ctrl+B, затем D           отсоединиться (сервер продолжает работать)
tmux attach -t dome       вернуться
```
