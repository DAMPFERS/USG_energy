# МКИ 2026 — энергосистема купола

Сервер игрового кейса «Энергетика»: агрегирует умные реле (13 линий), моделирует
солнечную генерацию и аккумулятор, ведёт сценарий игры и отдаёт веб-панель участникам.
Интерфейс участников — на английском (международные игры); консоль организатора — на русском (команды на английском).

## Запуск

```
pip install -r requirements.txt
python -m server              # http://<ip-сервера>:8000
python -m server --reset      # начать игру заново (стереть историю, терминал, состояние)
python -m server --demo       # демо-версия: 12 ч прогноза, старт сразу при запуске (см. ниже)
python -m admin               # консоль организатора (на этом же компьютере)
python -m admin --url http://<ip-сервера>:8000 --token <admin_token>
```

Для отладки в `config/server.yaml` стоит `clock.mode: sim` (время идёт ×20, старт — `clock.start`).
На игре поставьте `clock.mode: real`. Пошаговая инструкция для площадки — [LAUNCH.md](LAUNCH.md).

## Демо-версия

`python -m server --demo` — для демонстрации работы системы. Основная игра (`mission.yaml`, старт 27.10 в 11:30)
не меняется. Демо (`config/scenarios/demo.yaml`):

* начинается **сразу в момент запуска сервера** (`start: now`) и длится 12 часов;
* берёт окно прогноза основного кейса **Сол 2, 06:00–18:00**: восход, пик генерации, пылевая буря 13:00–16:30,
  вечерний спад (другое окно — `start_mars`). На графике — прогноз солнца на все 12 часов, генерация и потребление;
* каждый запуск — с чистого листа; логи демо — `logs/*_demo.*`, история основной игры не затрагивается;
* часы — `clock` в `demo.yaml` (переопределяет `server.yaml`): `mode: real` — 12 реальных часов,
  `mode: sim, speed: 20` — 12 часов за 36 минут.

Консоль организатора к демо подключается как обычно: `python -m admin`.

## Время купола

Игра — один большой сценарий на 50 часов: начало 27.10 в 11:30 (заселение) = **Сол 1, 11:30**
(`config/scenarios/mission.yaml`: `start`, `start_mars`, `duration_h`).

* Участники видят **марсианское время**: сол длится 24 ч 40 мин — после 23:59 часы идут
  24:00…24:39, затем начинается следующий сол с 00:00. Конец игры — Сол 3, 12:10.
* Сервер привязан к реальному времени: в режиме `real` время купола считается от системных часов машины.
  Если сервер был выключен, после запуска игра продолжается **с текущего момента**, а пропущенный
  промежуток на графике участников отмечен штриховкой «NO LINK», в терминал приходит сообщение о
  восстановлении связи. Заряд АКБ за время простоя не меняется.
* В режиме `sim` точка отсчёта сохраняется в `logs/clock_<сценарий>.json`, поэтому после перезапуска
  ускоренное время тоже продолжается. Новый `clock.start` подхватывается после `--reset`.

## Запуск под Linux

Нужен Python 3.10+ (проверено на 3.10 и 3.12).

```
sudo apt install python3 python3-venv git
git clone https://github.com/DAMPFERS/USG_energy.git && cd USG_energy
git checkout dome-1                    # на машине второго купола — dome-2
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m server                       # в отдельном терминале: python -m admin
```

* В режиме `clock.mode: real` время купола считается от системного времени машины — проверьте часовой пояс
  (`timedatectl`, при необходимости `sudo timedatectl set-timezone Europe/Moscow`).
* Сервер слушает порт 8000 — если включён файрвол: `sudo ufw allow 8000/tcp`.

## Ветки куполов

Куполов два, у каждого свой щиток и свой экземпляр сервера:

| Ветка | Что в ней |
|---|---|
| `main` | общий код, сценарии, веб-панель, консоль организатора |
| `dome-1`, `dome-2` | то же + конфигурация щитка своего купола (`config/server.yaml`: линии, реле, ключи) |

Обновление:

```
# разработчик: изменения кода — в main, затем влить в ветки куполов
git checkout dome-1 && git merge main && git push
git checkout dome-2 && git merge main && git push

# машина купола
git pull && python -m server
```

Чтобы слияние проходило без конфликтов, конфигурацию щитков меняйте только в ветках куполов.
Логи (`logs/`) в git не попадают; `config/line_map.yaml` создаётся на машине командой `name` в консоли организатора.

Организатор меняет параметры АКБ и правила из консоли, и они записываются в `config/server.yaml`
на машине купола. Перед `git pull` закоммитьте их в ветку купола или отложите (`git stash`),
иначе git откажется обновляться.

## Игровая механика

Аккумулятор один (`battery` в `config/server.yaml`): ёмкость, заряд на старте, максимальные мощности
заряда и разряда. Баланс «генерация − потребление» идёт в АКБ: излишек заряжает его (до `max_charge_kw`,
остальное и всё при полном АКБ теряется), дефицит покрывается разрядом (до `max_discharge_kw`).

Три игровые ситуации (параметры — `rules` в `config/server.yaml`, время игровое):

| Ситуация | Условие | Что происходит |
|---|---|---|
| **Перегруз** | потребление > `max_kw` | предупреждение и обратный отсчёт `overload_grace_min` (5 мин) на панели. Если потребление не снизилось — **блэкаут**: выключаются все линии, без блокировки, участники могут включить их снова |
| **Избыток** (нижняя граница) | генерация − потребление > `max_charge_kw` (АКБ подключён и не полон) | предупреждение и отсчёт `surplus_grace_min` (5 мин). Если избыток не снизился — АКБ **отключается** на `battery_off_min` (15 мин): не заряжается и не разряжается |
| **Дефицит** | потребление > генерация + доступный разряд АКБ | через `deficit_grace_s` (10 с) линии отключаются **по приоритету** — от #13 к #1, пока дефицит не исчезнет — и блокируются на `deficit_lock_min` (15 мин) |

* Нижняя граница коридора = генерация − `max_charge_kw`, она меняется вместе с солнцем. На панели
  участников это отдельный показатель «Min load», линией на графике она не рисуется.
* Предупреждение снимается, если нарушения нет `clear_s` секунд подряд. Короткие провалы
  отсчёт не сбрасывают, а только приостанавливают.
* **Приоритеты линий** (1–13) участники расставляют на своей панели (выпадающий список у каждой линии).
  Приоритеты уникальны: при выборе занятого номера линии меняются местами. 1 — самая важная линия, отключается последней.
* **Перезапуск**: состояние (АКБ, блокировки, приоритеты, отсчёты, статистика) и история сохраняются
  в `logs/`, после перезапуска игра продолжается.

## Сценарий

`config/scenarios/mission.yaml` — сообщения терминала по расписанию (`at: "2 13:00"` — сол и время купола,
`level`, `text`).

### Генерация и прогноз

Генерация складывается из двух составляющих:

```
генерация = солнце(t) × (1 − пыль(t) / 100) × коэффициент solar × (1 ± флуктуации 5 %)
```

* **Солнце** (низкочастотная составляющая) — `data/forecast.csv` (сол, время, кВт; шаг 5 минут, включая 24:00–24:35).
  Зависит только от положения Солнца. Это единственный прогноз, который видят участники и ЦУП:
  на графике «Sun forecast ± 5%» (разброс — `solar.fluctuation_pct` в `server.yaml`).
* **Запылённость** (высокочастотная составляющая) — `data/dust.csv` (сол, время, `dust_pct` 0–100; точки в любые
  моменты, между ними — линейно). 100 % — пылевая буря, генерация 0. Участникам не показывается ни в панели,
  ни в API — её видит только консоль организатора. Коллегам из георазведки (они готовят по ней спутниковые снимки)
  отдаётся выгрузка с шагом 1,5 ч:
  ```
  python -m server.export_dust                     # → dust_export.csv: n; sol; mars_time; earth_time; dust_pct
  python -m server.export_dust --step 45 --out d.csv
  ```
* **Коэффициент solar** — состояние панелей, задаёт организатор (`solar 0` после бури, затем повышать по мере
  очистки панелей; `solar 1` — чистые панели).

Сейчас в файлах демонстрационные данные: пик солнца около 12 кВт, запылённость 10–35 %, буря на Соле 2
с 13:00 до 16:30 (100 %).

### Графики исходных данных

```
python data/plot_csv.py                 # → data/plots/*.png
python data/plot_csv.py --factor 0.5    # генерация при коэффициенте панелей 0.5
python data/plot_csv.py --show          # дополнительно открыть окна matplotlib
```

Скрипт строит три графика: солнечный прогноз из `forecast.csv`, запылённость из `dust.csv` (с точками
исходных данных) и итоговую генерацию `солнце × (1 − пыль / 100) × factor`, а также сводный лист
`data/plots/00_summary.png`. Время — марсианское, с границами солов. Графики в git не попадают.

## Линии и потребители

13 потребителей заданы в `consumers` (`config/server.yaml`), по модулям:

| Модуль | Розетки | Освещение |
|---|---|---|
| MAIN (главный модуль) | `MAIN-S1`, `MAIN-S2` | `MAIN-L` |
| FABLAB (мастерская) | `FAB-S1`, `FAB-S2` | `FAB-L` |
| BIOLAB | `BIO-S1`, `BIO-S2` | `BIO-L` |
| HAB 1 (жилой модуль) | `HAB1-S` | `HAB1-L` |
| HAB 2 (жилой модуль) | `HAB2-S` | `HAB2-L` |

По умолчанию линии 1–13 привязаны к ним по порядку. На площадке:

```
blink 4            линия 4 помигает 3 раза — смотрим, где
name 4 BIO-L       линия 4 = освещение BIOLAB (если BIO-L был на другой линии — линии меняются)
names              текущая привязка
```

Привязка сохраняется в `config/line_map.yaml` и переживает перезапуск сервера.

## Консоль организатора

`python -m admin` — терминальное приложение: марсианское и земное время, статус игры, линии (приоритет,
вкл/выкл/блок/дефицит), генерация, потребление, верхняя и нижняя границы, отсчёты нарушений, АКБ и
сообщения терминала участников. Внизу командная строка, `F1` — справка, `↑/↓` — история команд.
URL и токен по умолчанию берутся из `config/server.yaml` (`port`, `admin_token`).

| Команда | Что делает |
|---|---|
| `on 3`, `off 1-4`, `off all` | включить / выключить линии (номер, ключ, список `1,3,5`, диапазон, `all`) |
| `lock BIO-L 15 Repair` | заблокировать (и выключить) на 15 игровых минут с причиной; без минут — до `unlock` |
| `unlock 3` | снять блокировку: админа или после дефицита |
| `prio 3 13`, `prio` | задать приоритет линии / список приоритетов |
| `max 9.5` | верхняя граница коридора (сразу + в `server.yaml`) |
| `set overload_grace_min=5 battery_off_min=15`, `set` | правила (сразу + в `server.yaml`) / список правил |
| `bat capacity_kwh=40 max_charge_kw=5 max_discharge_kw=6` | параметры АКБ (сразу + в `server.yaml`) |
| `bat soc=50`, `bat charge_kwh=10` | текущий заряд АКБ |
| `bat off 10`, `bat on`, `bat` | отключить АКБ на 10 мин (без минут — до `bat on`) / подключить / параметры |
| `crisis pause\|resume\|cancel` | заморозить отслеживание нарушений / продолжить / сбросить отсчёты, снять блокировки после дефицита, подключить АКБ |
| `solar 0`, `solar 0.5`, `solar 1` | коэффициент генерации — состояние панелей (0 после бури, повышать по мере очистки) |
| `msg WARN Text...` | сообщение в терминал участников |
| `time 2 13:30` | перемотка на Сол 2, 13:30 (только `clock.mode: sim`) |

Действия консоли в терминал участников **не пишутся** (кроме `msg`) — объявляйте их сами.
Все действия логируются в `logs/actions_<сценарий>.log`.

HTTP API консоли (заголовок `X-Admin-Token`) описан в начале `server/app.py`.

## Реальные реле

В `config/server.yaml` у линии: `driver: tuya`, `tuya: {device_id, local_key, ip}`
(из `smart_rele/devices.json`). `scale` переводит реальные Вт в игровые кВт.
Реле, которое не отвечает, отображается как «NO LINK» и в сумму не входит.
Сейчас все 13 линий — эмуляторы (`driver: sim`); данные реальных реле обоих щитков
оставлены закомментированными в конце `config/server.yaml`.

## Реальные солнечные панели

Сделайте класс с методами `start()`, `stop()`, `power_kw()`, `set_factor(f)` (см.
`SimSolarSource` в `server/solar.py`) и подключите его в `server/__main__.py` по `solar.source`.
