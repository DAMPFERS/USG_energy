# МКИ 2026 — энергосистема купола

Сервер игрового кейса «Энергетика»: агрегирует умные реле (13 линий), моделирует
солнечную генерацию и аккумуляторы, ведёт сценарий дня и отдаёт веб-панель участникам.
Интерфейс участников — на английском (международные игры); консоль организатора — на русском (команды на английском).

## Запуск

```
pip install -r requirements.txt
python -m server              # http://<ip-сервера>:8000
python -m server --reset      # начать игровой день заново
python -m server --scenario config/scenarios/day2.yaml
python -m admin               # консоль организатора (на этом же компьютере)
python -m admin --url http://<ip-сервера>:8000 --token <admin_token>
```

Для отладки в `config/server.yaml` стоит `clock.mode: sim` (день идёт ×20).
На игре поставьте `clock.mode: real`.

## Структура

```
config/server.yaml          сервер: порт, часы, потребители, линии (реле), источник генерации
config/line_map.yaml        какая линия какого потребителя питает (создаётся командой name в админке)
config/scenarios/day1.yaml  сценарий дня: фазы, коридор, АКБ, события, последствия
data/forecast_day1.csv      прогноз солнца: time,forecast_kw,sigma_kw
server/
  relays.py    опрос реле в отдельном потоке (tuya — реальные, sim — эмулятор)
  solar.py     прогноз из CSV + генерация в отдельном потоке (прогноз × factor + шум)
  battery.py   модель АКБ (ёмкость, мощность, пик, перегруз → защита, деградация)
  scenario.py  загрузка сценария
  engine.py    игровой движок: баланс, коридор, штрафы, события, переопределения админа, сохранение
  linemap.py   привязка «номер линии → потребитель»
  terminal.py  журнал сообщений терминала (logs/terminal_<день>.log)
  app.py       HTTP API (участники + /api/admin/*)
  telemetry.py телеметрия для ЦУП (REST + WebSocket, см. ISG_Energy_telemetry.md)
admin/        консоль организатора (Textual): client.py — API, commands.py — команды, console.py — экран
static/       веб-панель участника
logs/         terminal_*.log, telemetry_*.csv (история), actions_*.log (действия), state_*.json
```

## Игровая механика

* **Баланс**: генерация − потребление идёт в **активный АКБ** (выбирают участники).
  Излишек сверх `max_charge_kw` или при полном АКБ теряется; дефицит покрывается разрядом
  до `peak_discharge_kw`. Работа выше `max_discharge_kw` дольше `overload_tolerance_s` →
  АКБ уходит в защиту на `fault_recovery_min`.
* **Коридор** `[min_kw, max_kw]` — по суммарному потреблению линий.
  Выход за границы → предупреждение в терминале и обратный отсчёт `grace_s` →
  последствие (`on_overload` / `on_underload` / `on_deficit`): отключение линий
  (`auto`, `all`, `top:N`, список) на `duration_min`. Пока последствие действует, такое же
  нарушение повторно не наказывается.
* **Блокировки линий**: `locked_lines` в фазе (на всю фазу) и `lock_lines` в событии
  (на `duration_min`). Линию можно указать номером (`3`) или ключом потребителя (`BIO-S2`) —
  ключом надёжнее, т.к. соответствие реле и потребителей выясняется на площадке. Заблокированную линию участники включить не могут; если её
  включили физически — сервер выключит.
* **Перезапуск**: состояние (АКБ, блокировки, сработавшие события, статистика) и
  история сохраняются в `logs/` — после перезапуска игра продолжится.

## Линии и потребители

13 потребителей заданы в `consumers` (`config/server.yaml`): розетки жилых модулей 1 и 2
(`HAB1-S`, `HAB2-S`), по две линии розеток в мастерской, биореакторе и модуле управления
(`WS-S1/2`, `BIO-S1/2`, `CTL-S1/2`) и освещение пяти модулей (`HAB1-L`, `HAB2-L`, `WS-L`, `BIO-L`, `CTL-L`).
По умолчанию линии 1–13 привязаны к ним по порядку. На площадке:

```
blink 4            линия 4 помигает 3 раза — смотрим, где
name 4 BIO-L       линия 4 = освещение биореактора (если BIO-L был на другой линии — линии меняются)
names              текущая привязка
```

Привязка сохраняется в `config/line_map.yaml` и переживает перезапуск сервера и смену дня.

## Консоль организатора

`python -m admin` — терминальное приложение: время, статус дня и фаза, линии (вкл/выкл/блок/авария),
генерация, потребление, коридор, нарушения (обратный отсчёт, действующие последствия), АКБ и
сообщения терминала участников. Внизу командная строка, `F1` — справка, `↑/↓` — история команд.
URL и токен по умолчанию берутся из `config/server.yaml` (`port`, `admin_token`).

| Команда | Что делает |
|---|---|
| `on 3`, `off 1-4`, `off all` | включить / выключить линии (номер, ключ, список `1,3,5`, диапазон, `all`) |
| `lock BIO-L 15 Repair` | заблокировать (и выключить) на 15 игровых минут с причиной; без минут — до `unlock` |
| `unlock 3` | снять любую блокировку: админа, сценария, аварийную, блокировку фазы |
| `corr min 4 10`, `corr max 7.5` | переопределить границу коридора на N минут или до `corr reset [min\|max]` |
| `bat A soc=50 max_discharge_kw=3 status=ok` | изменить параметры АКБ (`bat fields` — список полей) |
| `active B` | принудительно сменить активный АКБ |
| `crisis pause\|resume\|cancel` | нарушения коридора/дефицит: заморозить отсчёт и наказания / снять отсчёт, последствия и аварийные отключения |
| `phase pause\|resume\|cancel` | текущая фаза сценария (коридор, солнце, блокировки): пауза до `resume` / отмена до конца дня |
| `solar 0.5` | масштаб генерации 0.0–2.0, умножается на коэффициент фазы (буря 0.3 × 0.5 = 0.15) |
| `msg WARN Text...` | сообщение в терминал участников |
| `time 13:30` | перемотка (только `clock.mode: sim`) |

Действия консоли в терминал участников **не пишутся** (кроме `msg`) — объявляйте их сами.
Все действия логируются в `logs/actions_<день>.log`, переопределения сохраняются в `state_<день>.json`.

HTTP API консоли (заголовок `X-Admin-Token`) описан в начале `server/app.py`.

## Телеметрия для ЦУП

Только чтение, в Вт / А / А·ч: `WS /ws/telemetry` (поток раз в секунду) и
`GET /api/telemetry`, `/api/telemetry/meta`, `/api/telemetry/forecast`, `/api/telemetry/history`.
Настройки — раздел `telemetry` в `config/server.yaml`, описание протокола — [ISG_Energy_telemetry.md](ISG_Energy_telemetry.md).
У линий в `meta` и в срезе есть поле `key` — ключ потребителя.

## Реальные реле

В `config/server.yaml` у линии: `driver: tuya`, `tuya: {device_id, local_key, ip}`
(из `smart_rele/devices.json`). `scale` переводит реальные Вт в игровые кВт.
Реле, которое не отвечает, отображается как «NO LINK» и в сумму не входит.
Сейчас все 13 линий — эмуляторы (`driver: sim`); данные реальных реле обоих щитков
оставлены закомментированными в конце `config/server.yaml`.

## Реальные солнечные панели

Сделайте класс с методами `start()`, `stop()`, `power_kw()`, `set_factor(f)` (см.
`SimSolarSource` в `server/solar.py`) и подключите его в `server/__main__.py` по `solar.source`.
