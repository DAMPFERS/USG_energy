# Телеметрия энергосистемы купола для ЦУП

Для управления линиями нужно, чтобы в одной локальной сети с умным щитком был запущен сервер (занимается фактическим управлением линиями, задает игровые сценарии, предоставляет интерфейс). Для получения данных телеметрии необходимо подключиться к этому серверу: 

Сервер отдаёт данные двумя способами:

| Способ | Адрес | Когда использовать |
|---|---|---|
| **WebSocket (поток)** | `ws://<сервер>:8000/ws/telemetry` | основной канал: сервер сам присылает срез раз в секунду и сообщения терминала |
| **HTTP REST (опрос)** | `http://<сервер>:8000/api/telemetry...` | если WebSocket неудобен, для разовых запросов, для загрузки истории и прогноза |

Все ответы — JSON в кодировке UTF-8. Подключение только на чтение: через телеметрию нельзя
управлять линиями или АКБ.

---

## 1. Подключение

### Адрес




* Хост и порт — IP компьютера, на котором запущен сервер энергосистемы, порт по умолчанию `8000`
  (`config/server.yaml`: `host`, `port`). .
* Компьютер ЦУП должен быть в той же сети и видеть этот порт.




### CORS

Если панель ЦУП — веб-страница с другого адреса, GET-запросы из браузера разрешены
(`telemetry.cors_origins`, по умолчанию `["*"]`). На WebSocket CORS не действует.

## 2. Единицы и соглашения

| Величина | Единица | Поле |
|---|---|---|
| Мощность | Вт | `*_w` |
| Ток | А | `*_a` |
| Ёмкость / заряд АКБ | А·ч | `*_ah` |
| Напряжение | В | `voltage_v` |
| Время купола | `HH:MM`, ISO 8601 или минуты от полуночи | `time`, `game_time`, `t` |
| Метка отправки | Unix-время, секунды (дробное) | `ts` |

Важно:

* **Мощности игровые** — это мощности купола, которые видят участники (кВт купола × 1000).
  На реальных реле стоит множитель `scale`: лампа 60 Вт может соответствовать 1200 Вт купола.
  Реально измеренные реле значения передаются отдельно в `lines[].measured`.
* **Ток и А·ч АКБ** пересчитываются из мощности и энергии через номинальное напряжение АКБ:
  `I = P / U`, `А·ч = Вт·ч / U`. Напряжение каждой АКБ передаётся в `voltage_v`
  (по умолчанию 48 В, `telemetry.battery_voltage_v`; для отдельной АКБ — `voltage_v` в сценарии).
* **Знак тока и мощности АКБ:** `> 0` — заряд, `< 0` — разряд.
* **Время купола.** На игре оно совпадает с реальным местным временем. При отладке (`clock.mode: sim`)
  время купола идёт быстрее (`speed`, например ×20), поэтому для оси X графиков используйте
  `game_time` / `t`, а не `ts`.
* `t` — минуты от полуночи времени купола с дробной частью (`543.5` = 09:03:30). Удобно для оси X.

## 3. WebSocket `/ws/telemetry`

```
ws://<сервер>:8000/ws/telemetry
ws://<сервер>:8000/ws/telemetry?token=<токен>
```

### Что присылает сервер

Каждое сообщение — JSON-объект с полем `type`:

| `type` | Когда | Содержимое |
|---|---|---|
| `hello` | сразу после подключения | справочник: линии, источники, АКБ, параметры дня — см. [5.2](#52-справочник-get-apitelemetrymeta--hello) |
| `forecast` | сразу после `hello` | прогноз генерации W(t) на весь игровой день, шаг 15 мин — см. [5.3](#53-прогноз-генерации-wt-get-apitelemetryforecast) |
| `telemetry` | каждые `push_interval_s` (1 с) | текущий срез — см. [5.1](#51-текущий-срез-get-apitelemetry--telemetry) |
| `message` | при новом сообщении терминала | события игры: фазы, аварии, отключения — см. [3.2](#32-сообщения-терминала-message) |
| `pong`, `history`, `error` | в ответ на запросы клиента | см. ниже |

### 3.1. Запросы клиента

Клиент может отправлять JSON-запросы в тот же сокет. Отвечать на них не обязательно, поток идёт и так.

| Запрос | Ответ |
|---|---|
| `{"type": "ping"}` | `{"type": "pong", "ts": 1791363252.264}` |
| `{"type": "get_meta"}` | сообщение `hello` |
| `{"type": "get_forecast", "from": "12:00", "to": "16:00", "step_min": 5}` | сообщение `forecast` (все поля, кроме `type`, необязательны) |
| `{"type": "get_history", "since": 600.0}` | сообщение `history` — точки с `t > since` (без `since` — весь день) |

Неизвестный или некорректный запрос: `{"type": "error", "error": "..."}`. Соединение при этом не закрывается.

### 3.2. Сообщения терминала (`message`)

```json
{"type": "message", "n": 42, "ts": "2026-10-07 12:00:00", "level": "CRIT",
 "text": "ТРЕВОГА! Песчаная буря накрыла купол. Генерация солнечных панелей упала. ..."}
```

`level`: `INFO`, `WARN`, `CRIT`, `OK`. `n` — сквозной номер сообщения за день.
В поток попадают только сообщения, появившиеся после подключения. Весь журнал дня можно получить
через `GET /api/terminal?after=0` (без токена, это API панели участников).

### 3.3. Переподключение

Если сервер перезапустили или пропала сеть, соединение закроется. Переподключайтесь с паузой 2–5 с.
После переподключения снова придут `hello` и `forecast`. Пропущенные точки графика можно догрузить
запросом `get_history` с `since` = последний полученный `t`.

## 4. HTTP REST

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| GET | `/api/telemetry` | — | текущий срез (как `telemetry` в WebSocket) |
| GET | `/api/telemetry/meta` | — | справочник (как `hello`, без поля `type`) |
| GET | `/api/telemetry/forecast` | `from=HH:MM`, `to=HH:MM`, `step_min=15` | прогноз W(t) |
| GET | `/api/telemetry/history` | `since=<t>` | история дня с шагом `history_step_s` (30 с времени купола) |

Все параметры необязательны. По умолчанию прогноз строится на весь игровой день
(`08:00–20:00` для дня 1) с шагом `telemetry.forecast_step_min`.

Коды ответа:

* `200` — успешно;
* `400` — неверные параметры (например, `step_min=0` или больше 2000 точек);
* `403` — неверный токен;
* `503` — сервер только что запустился и ещё не посчитал первый такт, повторите через секунду.

Данные обновляются раз в секунду, чаще опрашивать `/api/telemetry` смысла нет.

## 5. Форматы данных

### 5.1. Текущий срез: `GET /api/telemetry` / `telemetry`

```json
{
  "type": "telemetry",
  "schema": 1,
  "seq": 1532,
  "ts": 1791363192.481,
  "game_time": "2026-10-07T09:03:12",
  "game_status": "running",
  "phase": "Утренний запуск",

  "generation": {
    "total_w": 5268.0,
    "sources": [
      {"id": "solar", "name": "Солнечные панели", "type": "solar",
       "power_w": 5268.0, "forecast_w": 4959.7, "sigma_w": 1092.8}
    ]
  },

  "consumption": {
    "total_w": 7667.0,
    "corridor": {"min_w": 3000.0, "max_w": 8000.0}
  },
  "balance_w": -2399.0,
  "deficit_w": 0.0,

  "lines": [
    {"id": 1, "name": "Линия 1", "on": false, "online": true, "status": "tripped",
     "power_w": 0.0, "reason": "Перегруз: аварийное отключение", "until": "09:10",
     "measured": {"power_w": 0.0, "voltage_v": 230.0, "current_a": 0.0}},
    {"id": 2, "name": "Линия 2", "on": true, "online": true, "status": "on",
     "power_w": 951.0, "reason": null, "until": null,
     "measured": {"power_w": 47.5, "voltage_v": 229.8, "current_a": 0.207}}
  ],

  "active_battery": "A",
  "batteries": [
    {"id": "A", "name": "АКБ-1 Литий-ион", "active": true, "status": "ok",
     "voltage_v": 48.0,
     "capacity_ah": 416.67, "nominal_ah": 416.67, "available_ah": 246.84, "soc_pct": 59.2,
     "current_a": -49.97, "power_w": -2398.5, "mode": "discharge",
     "max_charge_a": 83.33, "max_discharge_a": 83.33, "peak_discharge_a": 125.0,
     "fault_until": null}
  ]
}
```

#### Общие поля

| Поле | Описание |
|---|---|
| `schema` | версия формата (сейчас `1`). Добавление новых полей версию не меняет |
| `seq` | номер среза, растёт с каждым срезом |
| `ts` | момент формирования среза на сервере, Unix-время |
| `game_time` | время купола (ISO 8601, без часового пояса — местное время) |
| `game_status` | `before` — день ещё не начался, `running` — идёт, `finished` — закончился. Вне `running` баланс не считается, ток АКБ = 0 |
| `phase` | название текущей фазы сценария или `null` |

#### Генерация `generation`

| Поле | Описание |
|---|---|
| `total_w` | суммарная генерация, Вт |
| `sources[]` | генерация по источникам. Сейчас один источник — `solar` (солнечные панели). Реактор позже появится отдельным элементом (`"type": "reactor"`), формат не изменится — **не завязывайтесь на то, что источник один** |
| `sources[].power_w` | фактическая генерация источника, Вт |
| `sources[].forecast_w` | прогноз на текущий момент, Вт (для сравнения факт/прогноз) |
| `sources[].sigma_w` | ожидаемый разброс прогноза (1σ), Вт |

#### Потребление и баланс

| Поле | Описание |
|---|---|
| `consumption.total_w` | суммарное потребление включённых линий, Вт |
| `consumption.corridor.min_w`, `max_w` | допустимый коридор потребления в текущей фазе, Вт. Выход за коридор — нарушение |
| `balance_w` | генерация − потребление. `> 0` — излишек идёт в активную АКБ, `< 0` — АКБ разряжается |
| `deficit_w` | мощность, которую не покрыли ни генерация, ни АКБ. `> 0` — авария, скоро отключение линий |

#### Линии `lines[]`

| Поле | Описание |
|---|---|
| `id`, `name` | номер (1–12) и название линии |
| `on` | реле включено (`true`) / выключено (`false`) |
| `online` | реле отвечает. Если `false`, мощность линии неизвестна и в сумму не входит |
| `status` | `on`, `off`, `locked` (заблокирована сценарием), `tripped` (аварийно отключена защитой), `offline` (нет связи с реле) |
| `power_w` | потребляемая мощность линии, Вт купола (0, если выключена) |
| `reason`, `until` | причина блокировки и время купола `HH:MM`, до которого она действует (для `locked`/`tripped`), иначе `null` |
| `measured` | реальные показания реле: `power_w` (Вт), `voltage_v` (В), `current_a` (А). `null`, если реле не на связи |

#### Аккумуляторы `batteries[]`

| Поле | Описание |
|---|---|
| `id`, `name` | идентификатор (`A`, `B`, `C`) и название |
| `active` | этот накопитель сейчас принимает баланс. Активен всегда только один, его `id` — в `active_battery` |
| `status` | `ok`, `degraded` (ухудшены параметры, работает), `fault` (временная защита от перегрузки, до `fault_until`), `failed` (выведен из строя сценарием) |
| `voltage_v` | номинальное напряжение, по которому считаются ток и А·ч |
| `available_ah` | **доступная ёмкость** (текущий запас заряда), А·ч |
| `capacity_ah` | текущая полная ёмкость, А·ч (снижается при деградации) |
| `nominal_ah` | паспортная ёмкость, А·ч |
| `soc_pct` | уровень заряда, % от `capacity_ah` |
| `current_a` | **ток заряда/разряда**, А: `> 0` — заряд, `< 0` — разряд, `0` — АКБ не активна |
| `power_w` | то же в Вт |
| `mode` | `charge`, `discharge`, `idle` |
| `max_charge_a`, `max_discharge_a` | номинальные токи заряда и разряда, А |
| `peak_discharge_a` | кратковременный пиковый ток разряда, А. Долгая работа выше `max_discharge_a` уводит АКБ в `fault` |
| `fault_until` | время купола `HH:MM:SS` окончания защиты или `null` |

источников и АКБ, границы игрового дня для оси X.

### 5.3. Прогноз генерации W(t): `GET /api/telemetry/forecast`

Прогноз мощности солнечных панелей на игровой день с ожидаемым разбросом. Прогноз задан
заранее (метеоданные дня) и за день не меняется, поэтому его достаточно загрузить один раз.

```
GET /api/telemetry/forecast                               весь игровой день, шаг 15 мин
GET /api/telemetry/forecast?from=11:00&to=15:00&step_min=5
```

```json
{
  "type": "forecast",
  "schema": 1,
  "source": "solar",
  "date": "2026-10-07",
  "step_min": 15.0,
  "from": "08:00",
  "to": "20:00",
  "points": [
    {"t": 480.0, "time": "08:00", "forecast_w": 2610.0, "sigma_w": 860.0, "low_w": 1750.0, "high_w": 3470.0},
    {"t": 495.0, "time": "08:15", "forecast_w": 3160.0, "sigma_w": 920.0, "low_w": 2240.0, "high_w": 4080.0}
  ]
}
```

| Поле | Описание |
|---|---|
| `t`, `time` | момент времени купола: минуты от полуночи и `HH:MM` |
| `forecast_w` | ожидаемая генерация W(t), Вт |
| `sigma_w` | неопределённость прогноза (1σ), Вт. Растёт там, где ожидается облачность или буря |
| `low_w`, `high_w` | границы коридора `forecast_w ± sigma_w` (нижняя не ниже 0) — для заливки на графике |

Рекомендуемый график: линия `forecast_w`, полупрозрачная заливка между `low_w` и `high_w`,
поверх — фактическая генерация из `history` и потока `telemetry` (`generation.sources[].power_w`).

> Фактическая генерация может сильно отличаться от прогноза: события сценария (например, песчаная буря)
> снижают её, и прогноз этого заранее не показывает. Это часть игры.

### 5.4. История дня: `GET /api/telemetry/history`

Записи с начала игрового дня с шагом `step_s` (30 с времени купола). Нужна, чтобы при открытии
панели ЦУП сразу нарисовать графики за прошедшее время, а дальше дополнять их живыми срезами.

```
GET /api/telemetry/history               весь день
GET /api/telemetry/history?since=600.5   только точки с t > 600.5
```

```json
{
  "type": "history",
  "schema": 1,
  "step_s": 30.0,
  "samples": [
    {"t": 542.698, "time": "09:03",
     "generation_w": 5268.0, "consumption_w": 7667.0,
     "corridor": {"min_w": 3000.0, "max_w": 8000.0},
     "active_battery": "A",
     "lines_w": {"1": 0.0, "2": 951.0, "3": 0.0, "4": 562.0, "5": 673.0, "6": 1015.0,
                 "7": 1346.0, "8": 383.0, "9": 820.0, "10": 687.0, "11": 955.0, "12": 276.0},
     "batteries_ah": {"A": 247.12, "B": 166.67, "C": 41.52}}
  ]
}
```

`lines_w` — мощность каждой линии (ключ — `id` линии строкой), `batteries_ah` — доступная ёмкость каждой АКБ.

## 6. Примеры клиентов

### Python (WebSocket)

```bash
pip install websockets
```

```python
import asyncio
import json

import websockets

URL = "ws://192.168.1.50:8000/ws/telemetry"   # + "?token=..." если задан токен


async def main():
    while True:
        try:
            async with websockets.connect(URL) as ws:
                async for raw in ws:
                    msg = json.loads(raw)
                    if msg["type"] == "hello":
                        print("Подключено:", msg["day"])
                    elif msg["type"] == "forecast":
                        print("Прогноз:", len(msg["points"]), "точек")
                    elif msg["type"] == "telemetry":
                        bat = next(b for b in msg["batteries"] if b["active"])
                        print(f'{msg["game_time"]}  ген {msg["generation"]["total_w"]:.0f} Вт  '
                              f'потр {msg["consumption"]["total_w"]:.0f} Вт  '
                              f'АКБ {bat["id"]}: {bat["available_ah"]:.1f} А·ч, {bat["current_a"]:+.1f} А')
                    elif msg["type"] == "message":
                        print(f'[{msg["level"]}] {msg["text"]}')
        except (OSError, websockets.ConnectionClosed) as e:
            print("Нет связи:", e, "— переподключение через 3 с")
            await asyncio.sleep(3)


asyncio.run(main())
```

### JavaScript (браузер)

```js
const URL = 'ws://192.168.1.50:8000/ws/telemetry';

function connect() {
  const ws = new WebSocket(URL);
  ws.onmessage = (e) => {
    const msg = JSON.parse(e.data);
    switch (msg.type) {
      case 'hello':     /* построить список линий/АКБ из msg.lines, msg.batteries */ break;
      case 'forecast':  /* нарисовать W(t) из msg.points */ break;
      case 'telemetry': /* обновить показатели и добавить точку на график по msg.game_time */ break;
      case 'message':   /* вывести событие msg.level / msg.text */ break;
    }
  };
  ws.onclose = () => setTimeout(connect, 3000);   // переподключение
}
connect();
```

### Python (REST, опрос)

```python
import time

import requests

BASE = "http://192.168.1.50:8000"
H = {}   # {"X-Telemetry-Token": "..."} если задан токен

forecast = requests.get(f"{BASE}/api/telemetry/forecast", headers=H, params={"step_min": 10}).json()
history = requests.get(f"{BASE}/api/telemetry/history", headers=H).json()

while True:
    s = requests.get(f"{BASE}/api/telemetry", headers=H, timeout=3).json()
    for line in s["lines"]:
        print(line["id"], line["status"], line["power_w"])
    time.sleep(1)
```

## 7. Соответствие запросу ЦУП

| Что запросил ЦУП | Где взять |
|---|---|
| Состояние линий вкл/выкл | `lines[].on`, подробнее — `lines[].status` |
| Потребляемая мощность линий, Вт | `lines[].power_w`, сумма — `consumption.total_w` |
| Текущая генерация по источникам, Вт | `generation.sources[].power_w` (сейчас `solar`), сумма — `generation.total_w` |
| АКБ: доступная ёмкость, А·ч | `batteries[].available_ah` |
| АКБ: ток заряда/разряда, А | `batteries[].current_a` (`+` заряд, `−` разряд) |
| Прогноз генерации W(t) для графика | сообщение `forecast` / `GET /api/telemetry/forecast` |
| История для графиков | `GET /api/telemetry/history` или запрос `get_history` |
